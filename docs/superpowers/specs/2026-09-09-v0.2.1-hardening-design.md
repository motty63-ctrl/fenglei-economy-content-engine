# V0.2.1 Official Source Hardening Design

## Scope

V0.2.1 hardens the existing `source_fetch` and `factcheck` stages. It does not add stages, change artifact ownership, generate scripts, or enter V0.3.

## Architecture

Tavily remains discovery-only. A source router converts only deterministic official URLs into retrieval plans, ordered API, PDF, then static HTML. Unknown dataset, indicator, country, or year mappings never produce guessed API requests. All downloaded material remains owned by `source_fetch` and is indexed by `source_documents/index.json`.

Official API responses retain a sanitized request fingerprint, endpoint, JSON pointer, exact observation, response hash, and retrieval time. PDFs retain the raw file, normalized text, per-page text, hashes, and page locators. HTML shells and empty bodies are explicit failures.

Only evidence backed by an eligible source document and a valid locator may reach verification. Search snippets remain permanently ineligible. `verified` facts are downstream-allowed; `unverified` and `conflicted` facts are downstream-blocked.

## Security

Provider errors, URLs, headers, payloads, stage errors, and CLI output pass through centralized redaction. Secrets are injected only at transport time and never stored in retrieval plans or artifacts. Raw exception chaining is suppressed at network boundaries.

## Compatibility

The artifact dependency graph and owner stages are unchanged. `source_documents/index.json` and `facts.json` advance to schema 2.1 while readers retain safe defaults for older artifacts.
