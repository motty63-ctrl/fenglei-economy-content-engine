# V0.3 Content Planning and Script Design

## Scope

V0.3 converts valid V0.2.1 research artifacts into candidate editorial angles, one selected angle, and a 60–90 second Chinese spoken script. It creates only `angles.json`, `angle.md`, and `script.md`. Storyboards, TTS, video generation, Web UI, n8n, and publishing are outside this version.

The first acceptance question is: “为什么 BEA 显示 2.8%，World Bank 显示约 2.7938%，这两个美国实际 GDP 增长率为什么看起来不一样？” The supplied wording is a research prompt, not a title; the system must generate at least three materially different angles.

## Architecture

V0.3 uses a hybrid pipeline. A model proposes structured creative material; deterministic local policy decides which facts may be used, calculates evidence strength, scores and selects angles, checks originality, validates every script sentence, estimates spoken duration, and only then writes a valid artifact.

Generation receives `research.md`, questions, and a curated fact palette. It does not receive the original `source.md` body. The originality checker reads `source.md` after generation so the model cannot follow the source article’s prose or structure.

## Stages and ownership

| Stage | Owned artifact | Reads |
|---|---|---|
| `angle_generation` | `angles.json` | `facts.json`, `research.md`, `questions.json`, `source.md` for post-generation originality checks only |
| `angle_selection` | `angle.md` | `angles.json`, `facts.json` |
| `script_generation` | `script.md` | `angle.md`, `facts.json`, `research.md`, `source.md` for post-generation lint only |

Existing V0.1–V0.2.1 artifact ownership is unchanged. Invalid model output never becomes a valid canonical artifact. Stage failures and redacted diagnostics are persisted in `run.json`; rerunning starts at the failed stage. Upstream hash changes propagate `stale` according to the graph in `docs/v0.3/artifact-dependency-graph.md`.

## Fact contract

An assertable fact must satisfy all of:

- `claim_type == "fact"`
- `verification_status == "verified"`
- `allowed_downstream == true`
- at least one eligible evidence item remains traceable to its source

Unverified claims are excluded. Conflicted claims are excluded by default. A future explicit dispute mode may describe the existence of a disagreement, but it may not select one conflicting observation as settled truth. V0.3 CLI defaults to dispute mode off.

Every sentence is typed as `verified_fact`, `explanation`, `interpretation`, or `analogy`. Only `verified_fact` requires claim IDs. A deterministic undeclared-fact detector escalates sentences containing numbers, dates, named-institution conclusions, policies, or definitive data verbs; changing the model’s label cannot bypass the fact gate.

All numbers, years, percentages, currencies, named institutions, and policy names in a verified-fact sentence must occur in the cited claim or eligible evidence. V0.3 performs no model-authored forecasts, rates, or extrapolations. The sole permitted derived numeric relation is decimal rounding: local code may verify with `Decimal` that two eligible observations for the same metric/country/year differ only by displayed precision. The model cannot authorize this relation itself.

## Angle generation and selection

The provider proposes 3–5 distinct angles. Local code validates claim IDs, computes evidence strength, evaluates originality and false-conflict risk, then applies the seven-dimension policy in `docs/v0.3/angle-scoring-policy.md`. Unsupported facts, fabricated conflict, source copying, or lack of script-ready claims are hard rejections regardless of score.

For the first acceptance question, `2.8` and approximately `2.7938` may be framed as a precision/rounding difference only after that deterministic rounding check passes. They must not be described as contradictory institutional findings merely because their displayed precision differs.

The default selector chooses the highest eligible score, prioritizing evidence reliability, ordinary-person relevance, and 60–90 second explainability. Users may explicitly select another eligible `angle_id`; rejected candidates cannot be selected.

`angles.json` uses schema version `3.0` and records run/provider/policy metadata plus every proposal. Each candidate requires `angle_id`, `title`, `hook`, `core_question`, `core_insight`, `supporting_claim_ids`, `evidence_strength`, `audience_relevance`, `novelty`, `hook_strength`, `visual_potential`, `explainability`, `controversy_risk`, `total_score`, `eligibility`, `risk_notes`, `rejection_codes`, and an originality result. Locally computed fields overwrite any provider-supplied value. Rejected proposals remain visible for audit but never become selectable.

`angle.md` contains the chosen angle, why it matters, its core conclusion, the phenomenon → mechanism → judgment claim chain, and a deterministic “不能说什么” section derived from rejected/unverified/conflicted claims.

## Script generation

The provider returns a structured draft conforming to `docs/v0.3/script-contract.schema.json`. The renderer writes `script.md` only after all gates pass. Visible factual sentences end in one or more `〔claim:claim_NNN〕` markers. Claim markers, Markdown, and metadata are excluded from duration estimation.

The script must:

- estimate to 60–90 seconds at 4.0 spoken Chinese characters per second;
- open with a truthful hook that fits within the first five seconds;
- proceed through phenomenon, mechanism, and a final core judgment;
- contain at least one mechanism/explanation segment;
- finish with one clear judgment sentence;
- remain suitable for oral reading and contain no visual, storyboard, TTS, or production directions.

Hook contrast must be supported by the cited facts or framed as a question/misunderstanding. It cannot invent opposing positions, remove material qualifications, exaggerate a difference, or turn rounding differences into institutional disagreement.

## Originality policy

The model never receives the source article body. Post-generation checks compare candidate titles, hooks, insights, and the script against `source.md`:

- normalized contiguous overlap of 16 or more Chinese characters is blocked;
- overlap of 12–15 characters requires regeneration;
- normalized character 5-gram Jaccard above 0.50 is blocked and 0.35–0.50 requires regeneration;
- reuse of a source title, distinctive metaphor, named case, coined phrase, or three consecutive argumentative beats is blocked;
- unavoidable institution names, standard economic terms, and cited numeric observations are not sufficient alone to trigger rejection.

Candidates also undergo mutual-diversity checks. Paraphrases of the same core question and insight do not count toward the required three angles.

## Failure and retry behavior

Schema failure, provider failure, unknown claim IDs, fact-policy failure, originality failure, or quality-gate failure marks only the current stage failed. Existing valid upstream artifacts are preserved. Repeated execution reuses a valid artifact without calling the provider. `--force-stage angle_generation` invalidates `angle.md` and `script.md`; forcing selection invalidates only `script.md`.

Provider names, model identifiers, and prompt versions are recorded in stage state. Provider/network errors use the existing redaction boundary.

## Acceptance

Using the specified BEA/World Bank question and a V0.2.1 run with suitable verified facts, V0.3 must generate at least three distinct candidate angles, select one eligible angle, and produce a valid 60–90 second script. Every factual sentence must resolve to an allowed claim. Injected unsupported numbers, false conflict, copied phrasing, unverified claims, conflicted assertions, jargon-heavy copy, or overlong sentences must prevent `script.md` from becoming valid. All existing tests must continue to pass.
