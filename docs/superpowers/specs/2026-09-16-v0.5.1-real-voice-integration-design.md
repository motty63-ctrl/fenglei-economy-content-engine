# V0.5.1 Real Voice Integration Specification

## 1. Purpose

V0.5.1 replaces the deterministic silent placeholder used by V0.5 with production-eligible narration generated by a real `NarrationProvider`. The first production adapter is Azure AI Speech. The application remains provider-neutral: content, alignment, timeline, storyboard, and renderer code consume generic contracts and never import Azure SDK types.

This version stops after generating and validating the first real GDP narration. Real alignment and timeline compilation are allowed only after a persisted human approval of the exact audio SHA-256. V0.5.1 does not generate images, a final MP4, or any V0.6 artifact.

## 2. Scope

### 2.1 Included

- `AzureSpeechNarrationProvider` behind the existing `NarrationProvider` boundary.
- Configurable voice ID, language, speaking rate, pitch, and volume.
- Credentials loaded only from `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION`.
- Canonical mono, PCM signed 16-bit, 24 kHz WAV output.
- Provider-neutral native timing events normalized inside the Azure adapter.
- `audio/quality.json` with deterministic signal metrics and gate results.
- Explicit `provider_type` with `real` and `fake` values.
- A production eligibility gate that rejects fake providers, silence, near-silence, and insufficient voiced duration.
- A persisted human voice-review artifact bound to the exact audio hash.
- Automatic stale propagation from changed narration audio into alignment, timeline, renderer project, preflight, and render QA artifacts.
- Unit tests with fake SDK clients and one explicit opt-in Azure integration test.

### 2.2 Excluded

- ElevenLabs, Volcengine, or any second production provider.
- Rewriting or editing `script.json`, `script.md`, `narration.json`, or `narration.txt`.
- Real alignment before human approval of the first GDP narration.
- Timeline recompilation before human approval.
- Nikola adaptation, image generation, audio mixing, subtitles, or MP4 rendering.
- Voice cloning or custom-voice training.

## 3. Non-negotiable invariants

1. Azure is an adapter, not a business-layer dependency.
2. The provider receives only the already-normalized `narration_text`. It cannot edit, summarize, translate, or embellish it.
3. A production audio artifact must explicitly record `provider_type="real"`.
4. File existence, valid WAV headers, duration, or provider name alone never establish production eligibility.
5. `provider_type="fake"` and alignment method `deterministic_fake` are forbidden in production artifacts.
6. No secret, authorization header, SDK configuration object, or unsanitized exception is persisted or logged.
7. All signal metrics are computed locally from the canonical WAV bytes, not trusted from the provider.
8. The first real GDP run stops after `audio/quality.json` and awaits human listening review.
9. Alignment requires a persisted approval whose `audio_sha256` equals the current valid WAV hash.
10. Changing the WAV invalidates every timing- and renderer-dependent descendant.

## 4. Architecture

```text
narration.json + narration.txt
          |
          v
NarrationProvider (generic protocol)
          |
          +-- AzureSpeechNarrationProvider (infrastructure adapter)
          |
          v
canonical WAV bytes + provider-neutral native timing events
          |
          v
local canonical-format validation
          |
          v
local audio signal analysis / non-silence gate
          |
          +-- fail: audio bundle failed; downstream remains stale
          |
          v
audio/narration.wav
audio/metadata.json
audio/quality.json
          |
          v
STOP: human listening review
          |
          v
audio/review.json (explicit approval bound to audio SHA)
          |
          v
AlignmentProvider (native timing adapter or independent real aligner)
          |
          v
alignment.json -> timeline.json
```

Provider construction belongs at the CLI/composition boundary. `v05_pipeline.py`, alignment, timeline, storyboard, and renderer modules accept protocols and typed generic data only.

## 5. Provider-neutral contracts

### 5.1 Synthesis configuration

```python
class NarrationSynthesisConfig(StrictModel):
    language: str = "zh-CN"
    voice_id: str
    speaking_rate: float = Field(default=1.0, ge=0.5, le=2.0)
    pitch_semitones: float = Field(default=0.0, ge=-12.0, le=12.0)
    volume_gain_db: float = Field(default=0.0, ge=-20.0, le=10.0)
```

These values are generic. Each provider adapter translates them to its own request format. No Azure voice name or HD model is a class default.

### 5.2 Provider identity

```python
ProviderType = Literal["fake", "real"]

class NarrationProvider(Protocol):
    name: str
    model: str
    provider_type: ProviderType

    def synthesize(
        self,
        request: NarrationRequest,
        config: NarrationSynthesisConfig,
    ) -> NarrationAudioResult: ...
```

`FakeNarrationProvider.provider_type` is always `fake`. `AzureSpeechNarrationProvider.provider_type` is always `real`.

### 5.3 Provider-neutral timing event

```python
class NativeTimingEvent(StrictModel):
    event_type: Literal["word", "punctuation", "sentence"]
    audio_offset_ms: int = Field(ge=0)
    duration_ms: int | None = Field(default=None, ge=0)
    text_offset: int = Field(ge=0)
    text_length: int = Field(ge=0)
    text: str
    source: Literal["provider_native"] = "provider_native"
```

Azure SDK event classes are converted into this model inside `providers/azure_speech.py`. No Azure timestamp type crosses that file boundary.

### 5.4 Narration result

```python
@dataclass(frozen=True)
class NarrationAudioResult:
    audio_bytes: bytes
    native_timestamps: tuple[NativeTimingEvent, ...] = ()
    provider_request_id: str | None = None
```

`provider_request_id` may be persisted only when it contains no credential or request payload. It is for provider support correlation, not authentication.

## 6. Azure adapter contract

`AzureSpeechNarrationProvider` lives in `src/fanglei/providers/azure_speech.py` and is the only module allowed to import `azure.cognitiveservices.speech`.

### 6.1 Credentials

- Required environment variables: `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`.
- The provider factory checks presence without printing values.
- Credentials are passed directly to the SDK and never included in dataclass reprs, metadata, errors, or logs.
- Tests use sentinel values with a fake SDK client; live credentials are used only by an opt-in integration test.

### 6.2 Request construction

- Input text is the ordered concatenation of `NarrationSentence.narration_text` values.
- Sentence separators and approved pauses are represented without changing lexical content.
- Voice, language, rate, pitch, and volume come from `NarrationSynthesisConfig`.
- The adapter requests RIFF/WAV PCM signed 16-bit mono at 24 kHz.
- The returned bytes are independently parsed and validated by local code even when the SDK reports success.

### 6.3 Word boundaries

- Subscribe to Azure `WordBoundary` events before synthesis starts.
- Convert tick offsets to integer milliseconds using exact integer arithmetic.
- Preserve text offsets and lengths relative to the exact submitted narration text.
- Reject events outside text or audio bounds.
- Do not invent a numeric recognition confidence. Azure native boundaries are timing evidence, not ASR confidence scores.

### 6.4 Error handling

Provider errors are mapped to stable codes such as:

- `AZURE_TTS_CONFIGURATION_MISSING`
- `AZURE_TTS_AUTH_FAILED`
- `AZURE_TTS_RATE_LIMITED`
- `AZURE_TTS_NETWORK_FAILED`
- `AZURE_TTS_CANCELED`
- `AZURE_TTS_AUDIO_EMPTY`
- `AZURE_TTS_OUTPUT_INVALID`

Only the code, HTTP/status category when available, provider cancellation category, and a redacted message may reach `run.json` or console output.

## 7. Canonical audio contract

The accepted production file remains:

- container: WAV/RIFF
- codec: PCM signed 16-bit little-endian
- channels: 1
- sample rate: 24,000 Hz
- duration: positive integer milliseconds
- content hash: SHA-256 of exact WAV bytes

The format validator runs before signal analysis. A format failure prevents all audio artifacts from becoming valid.

`audio/metadata.json` schema version becomes `5.1` for newly generated audio and includes:

```json
{
  "schema_version": "5.1",
  "path": "audio/narration.wav",
  "format": "wav",
  "codec": "pcm_s16le",
  "sample_rate_hz": 24000,
  "channels": 1,
  "duration_ms": 0,
  "sha256": "...",
  "provider": "azure_speech",
  "provider_type": "real",
  "provider_model": "configured-at-runtime",
  "voice_id": "configured-at-runtime",
  "language": "zh-CN",
  "speaking_rate": 1.0,
  "pitch_semitones": 0.0,
  "volume_gain_db": 0.0,
  "native_timestamps": []
}
```

The literal values above describe fields, not defaults for provider model or voice.

The reader remains backward-compatible with V0.5 schema `5.0`. A legacy record without
`provider_type` is never production eligible; the loader may classify the known
`provider="fake"` legacy record as fake for migration purposes, but it must not infer
`provider_type="real"` for any legacy provider. Every newly written schema `5.1` record
requires an explicit provider type.

## 8. Audio non-silence gate

### 8.1 Artifact

`audio/quality.json` is owned by `audio_generation` and binds to the exact WAV SHA-256.

```json
{
  "schema_version": "5.1",
  "audio_sha256": "...",
  "provider": "azure_speech",
  "provider_type": "real",
  "duration_ms": 84000,
  "peak": 0.61,
  "peak_dbfs": -4.29,
  "rms": 0.12,
  "rms_dbfs": -18.42,
  "voiced_duration_ms": 61200,
  "voiced_ratio": 0.7286,
  "frame_duration_ms": 20,
  "thresholds": {
    "min_peak": 0.0001,
    "min_rms_dbfs": -50.0,
    "voiced_frame_rms_dbfs": -45.0,
    "min_voiced_duration_ms": 1000,
    "min_voiced_ratio": 0.15
  },
  "passed": true,
  "gate_reasons": [],
  "production_eligible": true
}
```

`peak` and `rms` are normalized to full-scale PCM in the range 0–1. A zero value has a JSON `null` dBFS representation rather than negative infinity.

### 8.2 Deterministic calculation

- Decode signed 16-bit mono PCM locally.
- `peak = max(abs(sample)) / 32768`.
- `rms = sqrt(mean(sample^2)) / 32768`.
- Split samples into non-overlapping 20 ms frames.
- A voiced frame has frame RMS at or above `voiced_frame_rms_dbfs`.
- `voiced_duration_ms` is the sum of voiced frame durations, capped at total duration.
- `voiced_ratio = voiced_duration_ms / duration_ms`.

### 8.3 Gate rules

All rules must pass:

- `provider_type == "real"`
- `peak >= min_peak`
- `rms_dbfs` is not null and is at least `min_rms_dbfs`
- `voiced_duration_ms >= min_voiced_duration_ms`
- `voiced_ratio >= min_voiced_ratio`

Failure reasons are stable codes:

- `AUDIO_PROVIDER_NOT_REAL`
- `AUDIO_SILENT`
- `AUDIO_PEAK_TOO_LOW`
- `AUDIO_RMS_TOO_LOW`
- `AUDIO_VOICED_DURATION_TOO_SHORT`
- `AUDIO_VOICED_RATIO_TOO_LOW`
- `AUDIO_SIGNAL_ANALYSIS_FAILED`

Thresholds are application configuration and provider-independent. A provider cannot lower or bypass them.

## 9. Atomic audio bundle

Audio generation is a three-output transaction:

- `audio/narration.wav`
- `audio/metadata.json`
- `audio/quality.json`

The provider call, format validation, and quality analysis complete in memory or a stage-local temporary directory before any artifact is marked valid. On success, all three are committed and registered together. On failure:

- the stage is `failed`;
- the candidate output is not registered as valid;
- any previously valid fake audio bundle is marked stale before the production attempt;
- alignment and all descendants remain stale;
- the redacted failure is stored in stage state.

## 10. Human listening gate

The production CLI stops immediately after the valid audio bundle. It prints only artifact paths and non-secret quality metrics.

After a successful production audio bundle, the run status becomes
`voice_review_pending`. After a matching approval is persisted it becomes
`voice_approved`. Neither status implies valid alignment or renderer readiness.

Human approval creates `audio/review.json`, owned by a new `voice_review` stage:

```json
{
  "schema_version": "5.1",
  "audio_sha256": "...",
  "status": "approved",
  "reviewed_at": "ISO-8601 timestamp",
  "checks": {
    "voice": true,
    "speaking_rate": true,
    "pauses": true,
    "number_pronunciation": true
  },
  "notes": ""
}
```

The approval contains no provider secret. Alignment requires a valid approval with an audio hash equal to the current WAV and metadata hashes. Regenerating audio automatically makes the approval and every downstream artifact stale.

## 11. Alignment boundary

The business alignment interface becomes provider-neutral and audio-aware:

```python
@dataclass(frozen=True)
class AlignmentRequest:
    narration: NarrationDocument
    audio: AudioMetadata
    audio_bytes: bytes
    native_timestamps: tuple[NativeTimingEvent, ...]
```

`AzureNativeTimingAlignmentProvider` converts generic `NativeTimingEvent` records into sentence spans. It does not import Azure SDK classes.

Production alignment records:

- `provider_type="real"`
- `method="native_timestamp"` or a real forced-alignment method
- `confidence_source="provider_native_timing"` or `provider_reported`
- numeric confidence only when the upstream provider genuinely supplies it
- complete sentence coverage and transcript/offset mapping evidence

Native timing without a numeric confidence is not converted to an invented `0.99` or `1.0`. The gate evaluates completeness and exact offset mapping for native timing; real forced alignment continues to use provider-reported numeric confidence thresholds.

`deterministic_fake` remains available to tests but is rejected by the production alignment gate.

## 12. Artifact dependency graph

```text
script.json
  -> narration.json
       -> narration.txt
       -> audio/narration.wav
            -> audio/metadata.json
                 -> audio/quality.json
                      -> audio/review.json
                           -> alignment.json
                                -> timeline.json
                                     -> renderer_project/
                                     -> render_manifest.json
                                          -> preflight_report.json
                                          -> render_qa.json
```

Actual alignment dependencies also include `narration.json`, audio bytes, metadata, quality, and review. Timeline retains its storyboard and visual-beat dependencies.

When the real WAV replaces the fake WAV, the following become stale automatically:

- `audio/metadata.json` until rewritten in the same bundle
- `audio/quality.json`
- `audio/review.json`
- `alignment.json`
- `timeline.json`
- `renderer_project/`
- `render_manifest.json`
- `preflight_report.json`
- `render_qa.json`

## 13. CLI and configuration

The production-safe command is separate from renderer preparation:

```powershell
python -m fanglei generate-voice RUN_ID `
  --provider azure `
  --voice-id VOICE_ID `
  --language zh-CN `
  --speaking-rate 1.0 `
  --pitch-semitones 0.0 `
  --volume-gain-db 0.0 `
  --force
```

Rules:

- `generate-voice` always stops after the audio bundle.
- It never runs alignment, timeline, Nikola, preflight, or render.
- It never accepts `--provider fake` in production mode.
- Azure credentials come only from the environment.
- Non-secret voice settings are recorded in metadata for reproducibility.
- Provider factories live in the CLI/composition layer.

After listening approval, a separate explicit command records review:

```powershell
python -m fanglei approve-voice RUN_ID \
  --confirm-voice \
  --confirm-speaking-rate \
  --confirm-pauses \
  --confirm-number-pronunciation
```

Alignment and timeline commands remain unavailable for that audio hash until this approval exists.

## 14. Security and observability

- Provider keys are read from environment variables at call time.
- Secret values are never accepted as CLI flags.
- Provider configuration objects suppress secret repr output.
- Exceptions pass through existing redaction utilities before persistence or display.
- Tests use sentinel secrets and assert they are absent from captured logs, errors, metadata, quality reports, and `run.json`.
- Safe observability includes provider name, provider type, model, voice ID, region alias only when non-sensitive, request ID, duration, quality metrics, and stable error code.

## 15. Testing strategy

### 15.1 Unit tests

- Generic provider configuration validation.
- Azure adapter request mapping with a fake SDK boundary.
- Voice/model values are configuration, not class constants.
- Azure SDK timing events become provider-neutral events.
- Credentials are loaded only from environment variables and are redacted everywhere.
- Canonical WAV parsing and rejection of invalid container, codec, channels, or rate.
- Exact silence, near-silence, short voiced bursts, and low voiced ratio are rejected.
- Ordinary non-silent speech-like fixtures pass and produce deterministic metrics.
- Fake provider output is rejected in production even if non-silent.
- The three-output audio bundle is atomic.
- Replacing WAV content stales review, alignment, timeline, renderer, preflight, and QA.
- Production alignment rejects fake confidence and fake timing methods.
- Azure-specific SDK objects never appear in generic models or artifacts.

### 15.2 Opt-in Azure integration test

The live test runs only with `RUN_AZURE_SPEECH_INTEGRATION=1`. It:

1. checks credential presence without printing values;
2. synthesizes a short fixed Chinese fixture;
3. validates canonical WAV format;
4. validates `provider_type=real`;
5. validates non-silence metrics;
6. validates provider-neutral native timing bounds;
7. prints only sanitized metadata and artifact paths.

### 15.3 GDP acceptance checkpoint

The accepted GDP run executes only:

```text
Azure TTS -> canonical narration.wav -> audio/metadata.json -> audio/quality.json -> STOP
```

Required evidence before presenting the file for listening:

- provider is `azure_speech`;
- provider type is `real`;
- canonical format gate passes;
- non-silence gate passes;
- peak, RMS, voiced duration, voiced ratio, and duration are recorded;
- alignment and timeline attempt counts do not increase;
- renderer and QA descendants are stale;
- no secret appears in artifacts or logs.

Only after the user approves voice, speaking rate, pauses, and number pronunciation may the implementation create `audio/review.json` and continue with real alignment and timeline compilation.

## 16. Acceptance criteria

V0.5.1 Phase A is accepted when:

- the real Azure adapter is replaceable through the generic protocol;
- the GDP WAV is audible and passes deterministic signal gates;
- the user manually approves its sound;
- no downstream timing or rendering stage ran before approval;
- all offline tests pass;
- the opt-in Azure integration test passes;
- artifacts and logs contain no credentials.

V0.5.1 Phase B is accepted later when the approved audio produces real, provider-evidenced sentence alignment and an audio-authoritative timeline. Phase B is not authorized by this specification review alone.
