# V0.4 Visual Planning Design

## Goal and scope

Transform current, valid `script.json` into renderer-agnostic `visual_beats.json`, then into renderer-specific `storyboard.json` and a human-readable `visual_plan.md`. V0.4 does not create images, audio, timestamps based on real audio, renderer projects, or MP4 files.

## Artifact ownership

- `visual_beats.json` is owned by `visual_planning` and depends on `script.json`, `facts.json`, and `angle.md`.
- `storyboard.json` is owned by `storyboard_generation` and depends on `visual_beats.json`, `script.json`, and `facts.json`.
- `visual_plan.md` is owned by `visual_plan_render` and depends on `storyboard.json`.

ArtifactRegistry remains the only writer. Hash changes propagate `stale` to descendants, and stale inputs fail closed.

## Semantic plan

`visual_beats.json` contains only cognitive purpose, narration sentence range, core visual relationship, key objects, emphasized objects, relative order, estimated duration, claim references, and recommended renderer. It never contains pixel coordinates, SVG paths, stroke annotations, or implementation directives.

Each script sentence has exactly one primary beat. A beat normally covers two or more related sentences so the plan is not one-picture-per-sentence. Facts visible in the plan must already exist in the script and retain the originating sentence and allowed claim IDs.

## Render plan

`storyboard.json` defines layout, normalized placement, appearance order, transitions, persistence, removal, and renderer directives. Each scene has exactly one primary route: `program_animation` or `stroke_story`. Exact text, numbers, years, institution names, and indicator names use deterministic text layers even when the primary route is stroke story.

Every cross-beat object uses a stable `object_id`. Scenes explicitly list `persistent_objects`, `inherited_objects`, `introduced_objects`, and `removed_objects`. An inherited or persistent object must have been introduced earlier and must not change factual meaning.

## Visual provenance

Every factual visible object records its `sentence_ids`, and records `claim_ids` when the corresponding sentence is a verified fact. Claim IDs must resolve to `verification_status=verified` and `allowed_downstream=true`. The planner may add decorative shapes, arrows, and metaphors, but cannot add a number, year, institution, indicator, or deterministic causal statement absent from the script.

## Timing

Timing remains relative and estimated. Beats and scenes store `order`, `estimated_duration_seconds`, and optional within-scene relative cues from 0 to 1. They do not store authoritative audio start/end timestamps. Exact synchronization is deferred to the TTS/timeline phase.

## Renderer selection

- Use program animation for exact numbers/text, rounding, comparisons, causal chains, and independently animated knowledge objects.
- Use stroke story for people, physical actions, story events, or one illustration that accumulates naturally.
- A scene never calls program animation “stroke drawing”. Deterministic overlays are separate from the scene's primary route.
- Single scene is preferred for one accumulating mechanism; dual semantic islands are limited to two independently drawable narrative regions; causal chain requires at least three supported states; comparison requires a shared dimension; numeric animation preserves precision and never invents magnitude.

## Quality gate

The storyboard is valid only when schema, artifact currency, sentence coverage, factual provenance, claim eligibility, stable-object continuity, relative timing, renderer feasibility, safe layout, narrative progression, and anti-PPT checks pass. It rejects one-scene-per-sentence plans, unknown or forward-inherited objects, exact facts rendered nondeterministically, unsupported causal labels, and final conclusions not represented visually.

## GDP acceptance

The accepted GDP script must produce 4–7 beats and a continuous plan showing `2.8%` and `2.7932%`, rounding to one decimal place, the source/indicator/year/precision checklist, and a closing hidden-decimal metaphor. The plan consumes existing V0.3 artifacts only and generates no media.
