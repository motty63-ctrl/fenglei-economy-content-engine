# V0.1 Phase 1 Design

## Scope

Phase 1 implements a local, artifact-first CLI pipeline:

```text
.txt / .md / pasted text -> normalized source.md -> questions.json -> research.md
```

It does not implement URL fetching, real model calls, video generation, Web UI, n8n, publishing, TTS, FFmpeg, or any V0.2 capability.

## Architecture

The CLI delegates to stage functions. `ingest` creates one independent directory under `runs/`, normalizes input without rewriting its meaning, writes `source.md`, and records the stage in `run.json`. `analyze` reads that artifact, calls an injected `AnalysisProvider`, validates its structured result, then writes `questions.json` and a question-centered `research.md`.

Files are the durable system of record. `run.json` records stage state, input/output hashes, timestamps, attempts, provider identity, and errors. Writes use a temporary sibling file followed by `os.replace`. A successful stage is reused when its input fingerprint and output hashes still match. Explicit `--force` snapshots current outputs under `.history/<stage>/` before replacement.

## Interfaces

- `ingest_file(path, runs_dir)` accepts only `.txt` and `.md` files.
- `ingest_text(text, runs_dir)` accepts pasted or stdin text.
- `analyze_run(run_id, runs_dir, provider, force=False)` analyzes an existing run.
- `AnalysisProvider.analyze(source)` returns `AnalysisResult`; providers never write artifacts.
- The deterministic mock provider performs lightweight sentence classification and creates research questions without claiming external verification.

## Artifacts

Each run is named `YYYY-MM-DD-NNN-topic-slug` and contains:

- `source.md`: YAML-like metadata header plus normalized source text.
- `questions.json`: core topic, key facts, author arguments, externally verifiable claims, research questions, and single-source dependency risks.
- `research.md`: organized around research questions, with source clues, verification tasks, suggested independent source categories, hypotheses, and a mandatory unverified-evidence warning.
- `run.json`: schema version, run identity, input metadata, overall status, and per-stage state.
- `.history/`: snapshots produced only by explicit forced reruns.

## CLI

```text
python -m fanglei ingest article.md
python -m fanglei ingest --text "pasted text"
python -m fanglei ingest --stdin
python -m fanglei analyze <run_id>
python -m fanglei analyze <run_id> --force
```

`--runs-dir` is a global option. Commands print the run ID and relevant artifact paths. Empty input and invalid paths fail without creating a partial run.

## Errors and recovery

CLI errors use stable exit codes: 2 for invalid/empty input, 3 for invalid input paths or extensions, 4 for unsafe or missing run IDs, 5 for provider failure, and 6 for artifact/schema conflicts. Provider failures persist `analyze.status=failed`; retrying `analyze` does not repeat ingestion. Unexpected user edits that invalidate recorded output hashes require `--force` before replacement.

## Tests

Pytest uses temporary run roots and does not access the network. Coverage includes txt, Markdown, pasted text, stdin, empty input, invalid paths/extensions, run ID traversal, idempotent analyze, forced snapshots, provider recovery, artifact contracts, and the complete ingest-to-analyze CLI flow.
