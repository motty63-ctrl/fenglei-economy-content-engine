# V1.0b Subtitle + Audio Mastering MVP Specification

## 1. Goal and scope

V1.0b adds two deterministic, downstream-only capabilities to the accepted V1.0a
visual core:

1. a sentence-level subtitle track compiled from the approved `script.json` and
   approved `alignment.json`; and
2. a loudness-normalized playback copy of the approved narration.

The GDP run is the calibration case. Research, facts, angle, script, narration,
voice review, alignment, timeline, storyboard, visual program, and all five V1.0a
primitive implementations are frozen inputs. V1.0b does not run an LLM, ASR, TTS,
or a new visual planner.

Out of scope: BGM, karaoke subtitles, word-level alignment, new primitives,
illustrations, external media, V1.0a renderer redesign, n8n, and any upstream
regeneration.

## 2. Architectural choice

V1.0b uses two independent artifact-producing stages and one deterministic render
adaptation step:

```text
approved script.json + approved alignment.json
    -> subtitle_generation
    -> subtitle_track.json

approved narration.wav + metadata + quality + voice review
    -> audio_mastering
    -> audio/mastered_narration.wav + audio_mastering.json

frozen V1.0a renderer project inputs
    + subtitle_track.json
    + mastered_narration.wav
    -> v1b_render_adaptation
    -> renderer_project_v1b/ + render_manifest_v1b.json
```

The implementation must not edit `visual_system_v1.py`, the five primitive
renderers, their schema, or their animation schedules. `SubtitleLayer` is a sibling
overlay layer. The V1.0b renderer adapter derives a new project from V1.0a output
and fails if its expected insertion anchors are absent; it does not silently patch
unknown HTML.

The original approved audio remains the sole timing authority. The mastered audio
is a playback derivative with the same content and effectively the same duration.
The renderer manifest records both hashes instead of pretending that the mastered
file is the alignment source.

## 3. Artifact ownership and dependencies

| Artifact | Owner stage | Dependencies |
|---|---|---|
| `subtitle_track.json` | `subtitle_generation` | `script.json`, `alignment.json` |
| `audio/mastered_narration.wav` | `audio_mastering` | `audio/narration.wav`, `audio/metadata.json`, `audio/quality.json`, `audio/review.json` |
| `audio_mastering.json` | `audio_mastering` | `audio/narration.wav`, `audio/metadata.json`, `audio/quality.json`, `audio/review.json`, `audio/mastered_narration.wav` |
| `renderer_project_v1b` | `v1b_render_adaptation` | `storyboard.json`, `timeline.json`, `subtitle_track.json`, `audio/mastered_narration.wav`, `audio_mastering.json` |
| `render_manifest_v1b.json` | `v1b_render_adaptation` | `renderer_project_v1b`, `timeline.json`, `subtitle_track.json`, `audio_mastering.json` |

Only the owner stage writes its artifacts. Hash changes propagate stale state through
the existing registry. A mastered-audio change must stale V1.0b renderer artifacts,
but it must not stale or rewrite alignment or timeline. A script or alignment change
must stale subtitles and the V1.0b renderer. V1.0a artifacts remain untouched.

## 4. Subtitle schema

`subtitle_track.json` uses strict schema `subtitle_track.v1`:

```json
{
  "schema_version": "subtitle_track.v1",
  "run_id": "2026-09-08-004-2024-us-real-gdp-growth",
  "script_id": "script_001",
  "timing_source": "approved_sentence_alignment",
  "source": {
    "script_path": "script.json",
    "script_sha256": "...",
    "alignment_path": "alignment.json",
    "alignment_sha256": "...",
    "alignment_audio_sha256": "..."
  },
  "layout": {
    "canvas_width": 1080,
    "canvas_height": 1920,
    "reserved_zone": {"x": 96, "y": 1480, "width": 888, "height": 260},
    "maximum_lines": 2,
    "default_font_size_px": 52,
    "minimum_font_size_px": 40,
    "line_height": 1.28,
    "horizontal_padding_px": 36,
    "vertical_padding_px": 24
  },
  "cues": [
    {
      "cue_id": "subtitle_sentence_001",
      "sentence_id": "sentence_001",
      "text": "同一个GDP，两个数字，到底谁错了？",
      "start_ms": 500,
      "end_ms": 3521,
      "font_size_px": 52,
      "lines": [
        {"line_id": "line_01", "text": "同一个GDP，两个数字，", "start_char": 0, "end_char": 12},
        {"line_id": "line_02", "text": "到底谁错了？", "start_char": 12, "end_char": 18}
      ],
      "emphasis_spans": [
        {"start_char": 3, "end_char": 6, "text": "GDP", "kind": "keyword"}
      ]
    }
  ],
  "validation": {
    "passed": true,
    "sentence_coverage": 1.0,
    "text_exact_match": true,
    "timing_exact_match": true,
    "issues": []
  }
}
```

Character offsets are zero-based Unicode code-point offsets with an exclusive end.
`text` is copied byte-for-byte at the Unicode string level from the approved script,
not from `alignment.sentences[].text` or ASR output. `start_ms` and `end_ms` are copied
exactly from the matching approved alignment sentence. Joining `lines[].text` must
reproduce `text` exactly; line breaks are presentation metadata and are never inserted
into the approved script.

## 5. Subtitle compilation rules

### 5.1 Source and timing

- Script and alignment artifacts must both be `valid`, with actual hashes matching
  `run.json`.
- Sentence IDs must have one-to-one, same-order, 100% coverage.
- Timing is sentence-level only. No proportional character timing, ASR replacement,
  padding, stretching, or timeline edits are permitted.
- A cue is visible on `[start_ms, end_ms)`. Natural gaps remain subtitle-free.
- Alignment timestamps must be monotonic, non-overlapping, positive-duration, and
  within the approved audio duration.

### 5.2 Deterministic line breaking

The line breaker uses display-width units rather than raw character count. CJK and
full-width characters count as 1.0 unit; ASCII letters and digits as 0.56; spaces as
0.33; narrow punctuation as 0.5. Candidate breaks are ranked in this order:

1. after sentence punctuation (`，。？！；：`);
2. after commas and approved phrase boundaries already present in the text;
3. between Unicode code points when no natural break fits.

For two lines, choose the legal break with the smallest width imbalance while keeping
both lines inside the measured width budget. Start at 52 px and reduce only through
the fixed token sequence `52, 48, 44, 40`. If no one- or two-line layout fits at
40 px, fail with `SUBTITLE_TEXT_OVERFLOW`; do not add a third line, truncate text, or
shrink indefinitely. Browser-measured width remains the final renderer QA authority.

Line fragments preserve every character exactly, including punctuation and Latin
capitalization. The GDP calibration must cover the longest approved sentence without
changing its wording.

### 5.3 Emphasis

Emphasis is optional and deterministic. A cue may contain at most two non-overlapping
spans and emphasized content may not exceed 40% of the cue's code points.

Eligible spans are:

- a numeric expression that is already a continuous substring of the script text;
- an uppercase acronym already present, such as `GDP`, `BEA`, or `API`; or
- a term from a versioned, local emphasis allow-list, provided it is an exact
  continuous substring of the cue.

The span's offsets and `text` must resolve exactly against the cue. Emphasis cannot
change wording, add a symbol, merge discontinuous words, or introduce an unsupported
concept. Selection preference is number, then acronym, then allow-listed core term.

## 6. SubtitleLayer renderer contract

`SubtitleLayer` is independent of semantic primitives:

```text
render_subtitle_layer(track: SubtitleTrack, theme: VisualTheme)
    -> SubtitleLayerBundle(html, css, javascript, qa_metadata)
```

Contract:

- exactly one fixed layer is mounted under `#root`, after visual scenes and before the
  audio element;
- it uses `theme.subtitle_reserved_zone` exactly and never changes content-safe-area
  geometry;
- cue activation is driven by the composition clock and exact cue milliseconds;
- it renders one cue at a time, one or two lines, with stable line wrapping from the
  artifact rather than browser auto-reflow;
- emphasis is rendered with nested spans but the accessible/plain text remains the
  exact approved sentence;
- the layer uses `pointer-events:none`, a dedicated z-index, and no selectors that
  target primitive classes;
- entering/exiting opacity may use existing motion tokens, but animation must remain
  inside the cue interval and may not change timing;
- no subtitle is rendered in alignment gaps;
- the renderer exports cue bounds and measured line bounds for QA.

Portrait defaults: zone `(96,1480,888,260)`, centered text, 52 px default, 40 px
minimum, line-height 1.28, maximum two lines, opaque-enough neutral backing, primary
ink, and the existing emphasis-primary color. Final contrast must be at least 4.5:1
for normal subtitle text and 3:1 for emphasized large text.

`visual_project_v1b.py` creates `renderer_project_v1b/` without modifying V1.0a
source. It reuses the accepted V1.0a project build, injects the independent layer via
strict named anchors, binds `assets/mastered_narration.wav`, and writes explicit
timing/playback provenance:

```json
{
  "timing_authority": {
    "path": "audio/narration.wav",
    "sha256": "original-approved-sha",
    "duration_ms": 60611
  },
  "playback_audio": {
    "path": "assets/mastered_narration.wav",
    "sha256": "mastered-sha",
    "source_sha256": "original-approved-sha",
    "duration_ms": 60611
  }
}
```

## 7. Audio mastering contract

### 7.1 Interface

Business logic depends on an engine-neutral interface, not FFmpeg output text:

```python
class AudioMasteringEngine(Protocol):
    name: str

    def master(
        self,
        source_path: Path,
        config: AudioMasteringConfig,
    ) -> AudioMasteringResult: ...
```

`AudioMasteringConfig` fixes target integrated loudness to `-16.0 LUFS`, maximum
true peak to `-1.0 dBTP`, output PCM format to WAV/PCM 16-bit/24 kHz/mono, and maximum
absolute duration delta to 20 ms. Targets are configuration values, not literals in
pipeline logic.

The first implementation is `FFmpegLoudnormMasteringEngine` using deterministic
two-pass `loudnorm`:

1. measure the approved input;
2. normalize using the measured values and configured targets;
3. measure the rendered output again;
4. independently probe codec, sample rate, channel count, and duration.

No `atrim`, silence removal, tempo filter, resampling for speed, fades, compression,
EQ, denoising, or content-dependent editing is allowed. Resampling solely to restore
the canonical 24 kHz output contract is permitted and must not alter duration beyond
the gate tolerance.

### 7.2 `audio_mastering.json`

```json
{
  "schema_version": "audio_mastering.v1",
  "run_id": "...",
  "engine": "ffmpeg_loudnorm",
  "method": "ebu_r128_two_pass",
  "config": {
    "target_integrated_lufs": -16.0,
    "maximum_true_peak_dbtp": -1.0,
    "maximum_duration_delta_ms": 20,
    "output_format": "wav",
    "output_codec": "pcm_s16le",
    "sample_rate_hz": 24000,
    "channels": 1
  },
  "input": {
    "path": "audio/narration.wav",
    "sha256": "...",
    "duration_ms": 60611,
    "integrated_lufs": -21.4,
    "true_peak_dbtp": -6.1
  },
  "output": {
    "path": "audio/mastered_narration.wav",
    "sha256": "...",
    "duration_ms": 60611,
    "integrated_lufs": -16.0,
    "true_peak_dbtp": -1.2,
    "format": "wav",
    "codec": "pcm_s16le",
    "sample_rate_hz": 24000,
    "channels": 1
  },
  "duration_delta_ms": 0,
  "gate": {"passed": true, "issues": []}
}
```

The report stores commands only as sanitized method/version metadata; it must not
store local absolute paths or environment dumps. The input SHA must equal the approved
voice-review SHA and the timeline's timing-authority SHA. The original WAV is never
overwritten.

## 8. QA gates

### 8.1 Subtitle artifact gate

Fail closed on:

- stale or hash-mismatched script/alignment;
- sentence coverage other than 100%, duplicate/missing/reordered IDs;
- cue text different from approved script text;
- cue timestamps different from approved alignment timestamps;
- non-monotonic, overlapping, zero-length, or out-of-bounds timing;
- zero lines, more than two lines, empty lines, or line reconstruction mismatch;
- font size below 40 px or estimated/measured width overflow;
- invalid, discontinuous, overlapping, or non-substring emphasis;
- subtitle bounds outside the reserved zone.

### 8.2 Renderer subtitle gate

Fail closed when browser measurement detects overflow, more than two rendered lines,
safe-area violation, collision with a primary visual object, missing cue coverage, a
visible cue during a gap, or mutation of primitive markup/state schedules. Capture
representative frames for the longest sentence, a numeric emphasis cue, a scene
transition, and the final cue. Automated checks find obvious failures; human mobile
readability remains an acceptance step.

### 8.3 Audio mastering gate

Fail closed unless all are true:

- input is the current approved real narration and all input hashes agree;
- output is WAV, PCM signed 16-bit little-endian, 24 kHz, mono;
- measured integrated loudness is within `-16.0 ± 0.5 LU`;
- measured true peak is `<= -1.0 dBTP`;
- absolute duration delta is `<= 20 ms`;
- output passes the existing non-silence/voiced-audio gate;
- no clipping, decode error, empty stream, or non-finite measurement exists;
- original narration bytes and hash are unchanged.

### 8.4 Combined render gate

The renderer must prove:

- timeline duration still comes from original approved narration;
- mastered playback duration passes the mastering tolerance;
- subtitle source hashes match the bundled files;
- all five frozen scenes and their frame ranges are unchanged;
- SubtitleLayer stays within the reserved zone;
- the output project has no blank-frame, overflow, or timeline-mismatch regression.

## 9. Failure recovery

Subtitle generation and audio mastering are independent and individually rerunnable.
A failure writes no valid output artifact. Temporary FFmpeg files live under a stage
temporary directory and are removed after success or failure. Atomic registry writes
prevent partial WAV/report pairs from becoming valid. Renderer adaptation is blocked
until both artifacts are valid. No failure reruns upstream content, TTS, alignment,
timeline, storyboard, or V1.0a visual generation.

## 10. Acceptance for the GDP calibration

- 14/14 subtitle cues map to the approved 14 script/alignment sentences.
- Every cue uses exact script text and exact alignment start/end milliseconds.
- Every cue fits one or two lines at 40 px or larger in the existing portrait reserved
  zone; no primary visual collision is detected.
- Numeric/core-word emphasis is limited, exact-substring, and deterministic.
- The mastered WAV measures `-16.0 ± 0.5 LUFS`, `<= -1.0 dBTP`, remains canonical
  24 kHz mono PCM16, and differs in duration by no more than 20 ms.
- Original narration, timeline, V1.0a project, and all frozen upstream artifacts retain
  their hashes.
- A V1.0b project passes preflight and the minimal visual/audio QA before any optional
  full calibration render is authorized.
