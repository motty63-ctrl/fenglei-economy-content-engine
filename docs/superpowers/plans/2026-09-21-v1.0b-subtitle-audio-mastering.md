# V1.0b Subtitle + Audio Mastering MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic sentence-level subtitles and EBU R128 narration loudness normalization without changing any accepted V1.0a or upstream timing/content artifact.

**Architecture:** Two independent artifact-first stages compile `subtitle_track.json` and a mastered playback WAV/report. A separate V1.0b adapter layers subtitles and mastered playback onto the frozen V1.0a renderer output while preserving the original narration/alignment/timeline as timing authority.

**Tech Stack:** Python 3.11+, Pydantic v2, pytest, FFmpeg/FFprobe, HTML/CSS/JavaScript, HyperFrames 0.8.20.

**Spec:** `docs/superpowers/specs/2026-09-21-v1.0b-subtitle-audio-mastering-design.md`

## Global Constraints

- Do not modify research, facts, angle, script, narration, voice review, alignment, timeline, storyboard, visual program, or V1.0a primitive implementations.
- Subtitle text comes only from approved `script.json`; ASR text is never substituted.
- Subtitle timing copies approved sentence alignment exactly and never modifies timeline.
- One or two lines only; font size never below 40 px.
- Mastering target is `-16.0 LUFS`; true peak must be `<= -1.0 dBTP`.
- No time-stretch, trimming, silence removal, TTS regeneration, BGM, or content edit.
- Original narration remains timing authority; mastered narration is playback-only.
- All new outputs use owner/hash/stale propagation and atomic writes.
- No full render until unit/integration tests, preflight, and GDP calibration QA pass.

## Review Focus

1. A long Chinese/Latin/numeric sentence must either fit two lines at 40 px or fail closed; it must never silently truncate or create a third line.
2. Script and alignment with the same count but different sentence order must fail rather than bind wrong timestamps.
3. An emphasis span with visually identical but non-identical Unicode text must fail exact-substring validation.
4. FFmpeg may report successful normalization while emitting a wrong rate/channel/codec; the post-probe must reject it.
5. A mastered WAV with an acceptable loudness result but altered duration must fail and never replace the renderer playback asset.
