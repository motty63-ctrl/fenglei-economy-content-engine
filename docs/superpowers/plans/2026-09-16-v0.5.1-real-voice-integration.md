# V0.5.1 Real Voice Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate a production-eligible Azure AI Speech narration, validate it with a deterministic non-silence gate, persist an audio-hash-bound human review, and preserve provider-neutral downstream interfaces.

**Architecture:** Azure is isolated behind `NarrationProvider`; the business pipeline receives generic synthesis configuration, canonical WAV bytes, and generic timing events. Audio format and signal quality are validated locally before an atomic three-artifact bundle becomes valid. The first GDP acceptance stops after audio generation and waits for explicit human approval before any real alignment or timeline work.

**Tech Stack:** Python 3.11+, Pydantic 2, Typer, pytest, `azure-cognitiveservices-speech>=1.45,<2`, standard-library PCM/WAV analysis.

**Spec:** `docs/superpowers/specs/2026-09-16-v0.5.1-real-voice-integration-design.md`

## Global Constraints

- Do not rewrite V0.5 history or modify `main` directly.
- Do not modify `script.json`, `script.md`, `narration.json`, or `narration.txt` content.
- The first live GDP execution stops after `audio/quality.json`.
- Do not run alignment, timeline, Nikola adaptation, preflight, or MP4 rendering before human voice approval.
- `provider_type="fake"` is forbidden in production audio and alignment artifacts.
- Azure credentials come only from `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION`.
- Never persist or print credentials, authorization headers, SDK configuration objects, or unsanitized exceptions.
- Canonical audio is WAV, PCM signed 16-bit little-endian, mono, 24 kHz.
- Provider-specific timestamp types remain inside the provider adapter.
- Future NarrationProvider adapters must not require changes to alignment, timeline, storyboard, or renderer business interfaces.
